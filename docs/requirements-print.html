Documento de Requerimientos

1. Introducción

El presente documento describe los requerimientos de negocio para un sistema de gestión integral de operaciones de cosecha agrícola. El sistema resuelve la falta de visibilidad, trazabilidad y control sobre la producción en campo, el rendimiento de los trabajadores y la liquidación de pagos por unidad recolectada (caja/kilo).

1.1 Problema que Resuelve

Los fundos agrícolas que operan bajo esquema de pago por pieza (piece-rate) enfrentan:

  • Registro manual propenso a errores: Cuadernos y planillas generan discrepancias en el conteo de cajas, pérdida de datos y conflictos con trabajadores.
  • Falta de visibilidad en tiempo real: Los supervisores no conocen el avance de la jornada hasta el cierre del día.
  • Liquidaciones lentas y opacas: Los trabajadores desconfían del cálculo de pagos cuando no pueden verificar sus propios registros.
  • Nula trazabilidad por paño/cuartel: No se sabe qué zonas rinden más ni dónde concentrar esfuerzos.
  • Imposibilidad de escalar: Al crecer la operación, los mecanismos manuales colapsan.

1.2 Propuesta de Valor

El sistema entrega control completo de la cadena operativa — desde la estructura de campos hasta la liquidación final — en una plataforma digital accesible desde dispositivos móviles, con identificación por QR y métricas en tiempo real.

3. Requerimientos

3.1 Gestión de Estructura de Campos

User Story: Como Administrador, quiero definir y organizar la estructura de mis campos productivos (fundos, paños, hectáreas y productos asociados), para tener un catastro digital actualizado de mi operación.

Criterios de Aceptación

  1. El Sistema permitirá al Administrador crear, modificar y desactivar Campos con nombre, ubicación y superficie total en hectáreas.
  2. El Sistema permitirá al Administrador crear, modificar y desactivar Paños dentro de un Campo, con nombre, superficie en hectáreas y Producto asociado.
  3. Cuando un Administrador asocia un Producto a un Paño, el Sistema registrará la asociación y la hará visible para Supervisores y el Dashboard.
  4. El Sistema mantendrá un catálogo de Productos con nombre y unidad de medida (caja o kilo).
  5. Si un Administrador intenta desactivar un Campo o Paño con registros de picking activos en la Jornada actual, el Sistema advertirá y solicitará confirmación antes de proceder.

3.2 Gestión de Trabajadores

User Story: Como Administrador, quiero registrar y gestionar a los trabajadores de la operación con sus datos esenciales y un identificador QR, para tener un padrón confiable y facilitar la identificación en campo.

Criterios de Aceptación

  1. El Sistema permitirá al Administrador crear, modificar y desactivar Trabajadores con nombre completo, RUT o identificador nacional, teléfono de contacto y rol asignado.
  2. Cuando un Trabajador es creado, el Sistema generará automáticamente un Badge QR único vinculado a ese Trabajador.
  3. El Sistema permitirá al Administrador regenerar el Badge QR de un Trabajador en caso de pérdida o deterioro.
  4. El Sistema soportará la asignación de roles: Administrador, Supervisor y Trabajador.
  5. Si un Administrador intenta desactivar un Trabajador con Liquidaciones pendientes de pago, el Sistema notificará la deuda pendiente y requerirá resolución antes de desactivar.

3.3 Configuración de Tarifas por Producto

User Story: Como Administrador, quiero configurar el valor a pagar por cada unidad recolectada según el tipo de producto, para que las liquidaciones se calculen de forma automática y precisa.

Criterios de Aceptación

  1. El Sistema permitirá al Administrador definir y modificar la Tarifa (valor monetario por unidad) para cada Producto.
  2. Cuando un Administrador modifica una Tarifa, el Sistema aplicará la nueva Tarifa únicamente a los registros creados a partir de la fecha de modificación.
  3. El Sistema conservará el historial de Tarifas con fecha de vigencia para garantizar la trazabilidad de pagos históricos.
  4. Si un Administrador intenta guardar una Tarifa con valor cero o negativo, el Sistema rechazará la operación y mostrará un mensaje descriptivo.

3.4 Registro de Picking en Campo

User Story: Como Supervisor, quiero registrar de forma rápida y confiable las cajas o kilos recolectados por cada trabajador en cada paño durante la jornada, para que la producción diaria quede documentada sin errores.

Criterios de Aceptación

  1. Cuando un Supervisor escanea el Badge QR de un Trabajador, el Sistema identificará al Trabajador y presentará el formulario de registro de picking.
  2. El Sistema permitirá al Supervisor registrar la cantidad de unidades recolectadas, el Paño de origen y la fecha/hora del registro.
  3. Cuando un Registro de Picking es guardado, el Sistema lo asociará automáticamente a la Jornada vigente.
  4. El Sistema permitirá al Supervisor corregir un Registro de Picking dentro de la misma Jornada, conservando el registro original como auditoría.
  5. Si el Supervisor intenta registrar picking para un Trabajador desactivado, el Sistema rechazará el registro.
  6. Si el Supervisor intenta registrar picking en un Paño desactivado, el Sistema rechazará el registro.

3.5 Consulta de Producción por Trabajador

User Story: Como Trabajador, quiero ver cuántas cajas o kilos he recolectado durante el día y en períodos anteriores, para conocer mi avance y verificar que mis registros son correctos.

Criterios de Aceptación

  1. El Sistema mostrará al Trabajador autenticado su total de unidades recolectadas en la Jornada actual.
  2. El Sistema mostrará al Trabajador un historial de producción por Jornada con detalle de Paño y cantidad.
  3. El Sistema mostrará al Trabajador el monto estimado a percibir en la Jornada actual basado en las Tarifas vigentes.
  4. Mientras un Trabajador consulta sus registros, el Sistema presentará únicamente los datos pertenecientes a ese Trabajador.

3.6 Liquidación y Pagos

User Story: Como Administrador, quiero que el sistema calcule automáticamente lo que se le debe a cada trabajador según sus registros de producción y las tarifas vigentes, para agilizar el proceso de pago y eliminar errores de cálculo manual.

Criterios de Aceptación

  1. Cuando un Administrador solicita generar una Liquidación para un período determinado, el Sistema calculará el monto total multiplicando las unidades registradas por la Tarifa vigente al momento de cada registro.
  2. El Sistema presentará el detalle de la Liquidación desglosado por Jornada, Paño y Producto para cada Trabajador.
  3. Cuando un Administrador marca una Liquidación como pagada, el Sistema registrará la fecha de pago y el monto abonado.
  4. El Sistema mantendrá un saldo de deuda pendiente por cada Trabajador (total liquidado menos total pagado).
  5. Si el monto abonado excede el saldo pendiente de un Trabajador, el Sistema rechazará la operación.

3.7 Métricas y Dashboard de Producción

User Story: Como Administrador, quiero visualizar indicadores clave de la operación (rendimiento por trabajador, producción por paño, costos por hectárea y rankings), para tomar decisiones informadas y optimizar la eficiencia de la cosecha.

Criterios de Aceptación

  1. El Sistema presentará en el Dashboard la producción total del día (unidades y monto) con actualización durante la Jornada.
  2. El Sistema mostrará un ranking de Trabajadores ordenado por unidades recolectadas en un período seleccionable.
  3. El Sistema mostrará la producción acumulada por Paño y por Campo en un período seleccionable.
  4. El Sistema calculará y presentará el costo por hectárea como el total de pagos dividido por la superficie cosechada.
  5. El Sistema permitirá al Administrador filtrar las métricas por Campo, Paño, Producto, Trabajador y rango de fechas.
  6. Cuando un Supervisor accede al Dashboard, el Sistema mostrará únicamente las métricas correspondientes a los Trabajadores y Paños bajo su supervisión.

3.8 Control de Acceso Basado en Roles

User Story: Como Administrador, quiero que cada usuario vea y haga solo lo que corresponde a su rol, para proteger la información sensible y mantener la integridad operativa.

Criterios de Aceptación

  1. El Sistema restringirá el acceso a funcionalidades según el rol del usuario autenticado: Administrador, Supervisor o Trabajador.
  2. El Administrador tendrá acceso completo a todas las funcionalidades del Sistema.
  3. El Supervisor tendrá acceso al registro de picking, consulta de producción de su equipo y métricas de su supervisión.
  4. El Trabajador tendrá acceso exclusivamente a la consulta de su propia producción y sus propias liquidaciones.
  5. Si un usuario intenta acceder a una funcionalidad no autorizada, el Sistema denegará el acceso.

3.9 Asignación de Supervisión

User Story: Como Administrador, quiero asignar trabajadores a supervisores y supervisores a paños, para que cada supervisor tenga responsabilidad clara sobre su equipo y zona de trabajo.

Criterios de Aceptación

  1. El Sistema permitirá al Administrador asignar uno o más Trabajadores a un Supervisor.
  2. El Sistema permitirá al Administrador asignar uno o más Paños a un Supervisor.
  3. Cuando un Supervisor accede al registro de picking, el Sistema mostrará únicamente los Trabajadores y Paños asignados a ese Supervisor.
  4. Si un Supervisor intenta registrar picking para un Trabajador no asignado a su supervisión, el Sistema rechazará la operación.

4. Roadmap por Fases

Fase 1 — Fundación Operativa (MVP)

  • Gestión de Campos, Paños y Productos (Req. 3.1)
  • Gestión de Trabajadores con Badge QR (Req. 3.2)
  • Configuración de Tarifas (Req. 3.3)
  • Registro de Picking en campo (Req. 3.4)
  • Consulta de producción por Trabajador (Req. 3.5)
  • Control de acceso básico por roles (Req. 3.8)

Fase 2 — Gestión Financiera

  • Liquidación y Pagos automáticos (Req. 3.6)
  • Asignación de supervisión (Req. 3.9)

Fase 3 — Inteligencia Operativa

  • Dashboard y métricas avanzadas (Req. 3.7)
  • Rankings y reportes exportables
  • Alertas de rendimiento anormal

Fase 4 — Escalamiento (Futuro)

  • Soporte multi-fundo con consolidación central
  • Modo offline con sincronización
  • Integraciones con sistemas contables y de RRHH
  • App móvil nativa para trabajadores

6. Restricciones de Negocio

  1. El Sistema debe ser operable desde dispositivos móviles en campo (smartphones/tablets).
  2. La interfaz del Trabajador debe ser simple y comprensible para personas con bajo nivel de alfabetización digital.
  3. El registro de picking debe completarse en menos de 10 segundos por operación para no retrasar la cosecha.
  4. Los datos financieros (tarifas, liquidaciones, pagos) son visibles únicamente para el rol Administrador.
  5. El Sistema debe soportar operación con conectividad intermitente en zonas rurales (Fase 4).
